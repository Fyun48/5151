## 步驟與實測

### Cycle 1（B → A）

1. **fence** 舊 primary（Synology）：`docker stop 5151-postgres-B`
2. **promote**（CasaOS）：`PG_CONTAINER=5151-postgres-A PG_CONTAINER_PEER=5151-postgres-B CONFIRM_FAILOVER=yes FENCED=yes bash drill.sh failover`
   → `step4 pg_is_in_recovery()=f`、`step5 新 primary 可寫 OK`
3. **HAProxy**：`fall 3 × inter 3s` 後自動改道（舊 primary 已停機時不需要動設定）
4. **建 slot**（新 primary 上）：`5151-create-slot.sh 5151-postgres-A standby_b`
5. **rejoin** 舊 primary：`5151-rejoin-standby.sh 5151-postgres-B 192.168.0.140 standby_b /var/services/homes/tori/5151-shadow-ha/shadow-ha/postgres-standby`
   → basebackup `38711/38711 kB` → `write standby.signal + recovery conf` → `pg_is_in_recovery()=t`、`receive == replay`
6. **驗證**：A 的 `pg_stat_replication` = `192.168.0.220 | streaming | async`；B `t`、in sync
7. **re-point** HAProxy 到新 primary（CasaOS）→ `pg-rw → 192.168.0.140 = f`、`pg-ro → 192.168.0.220 = t`

### Cycle 2（A → B，回到預設）

1. **fence** A、**promote** B（在 Synology 跑同一支 `drill.sh failover`）→ B `f`、可寫
2. **建 slot** `standby_a`（B 上）＋ `fix-pg-hba.sh`（`CONTAINER=5151-postgres-B`，idempotent、回 `reload issued`）
3. **rejoin** A：basebackup `38711/38711 kB`（slot `standby_a`）→ A `t`、in sync
4. **HAProxy 回到預設排序**：`5151-haproxy-install.sh /root/haproxy.cfg.tmpl 192.168.0.140 192.168.0.220 synology`
   → `pg-rw → 192.168.0.220 = f`、`pg-ro → 192.168.0.140 = t`

## 發現（都已處理）

1. **live HAProxy 設定是 CRLF**：`backup$` 這種 sed 比對會失手（會在 `\r` 後面再接一次 `backup`）。
   已把 `/opt/5151-shadow/haproxy/haproxy.cfg` 正規化為 LF。repo 的 `.gitattributes` 早就寫
   `*.cfg text eol=lf`，所以這是 **live-only 的漂移**。
2. **live 設定是單檔 bind mount，`sed -i` 會換 inode**：容器會一直掛在舊 inode，改完看起來「沒生效」，
   要 restart 才會重掛。→ 一律「就地覆寫內容 + 重啟」；`5151-haproxy-install.sh` 兩者都做。
3. **runbook §6 的 pg-rw re-point 確實必要（兩個方向都實測到）**：舊 primary 回來變成 standby 後，
   若 `pg_primary` 仍把它排在最前面且沒有 `backup` 標記，pg-rw 會打到唯讀節點（實測 `pg-rw → t`）。
4. **live 來源路徑是 `/opt/5151-shadow/haproxy/`**，不是 `~/5151-shadow-ha/…`（後者在兩台都只是舊工作副本）。
5. **容器內改設定會失敗**：`/usr/local/etc/haproxy/haproxy.cfg` 是唯讀掛載
   （`sed: ... Read-only file system`）。
6. `drill.sh failover` 的 `step6` 在「剛 promote、HAProxy 還沒 fall 完」時會印連線錯誤片段，這是預期；
   改由 `5151-target-probe.sh`（`select inet_server_addr(), pg_is_in_recovery()`）判定實際目標。
