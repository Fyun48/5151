# 抓取與列表查詢修正（2026-09-12）

基準版本：`112e00e3632d79f8167f79b3cd8d8c20afd3e505`。這是程式修正與驗證紀錄，不代表正式站已部署或樂屋已恢復入庫。

## 已確認的問題與修正

| 問題 | 修正 |
| --- | --- |
| 樂屋批次缺少 searchUrl，入庫 search_key 為空，會被共用搜尋範圍排除 | 批次保留涵蓋範圍，使用數字行政區 ID；有明確完整縣市／行政區地址的舊空鍵資料才修復關聯，不修改觀看、關注、時間與通知 |
| 樂屋沿用 591 縣市代碼與舊網址 | 公開頁確認台北 city=0、基隆 city=1、新北 city=2；採 /result 與 /item 路徑。其它縣市回報 UNSUPPORTED_REGION，避免猜代碼 |
| 樂屋每次從前幾頁開始，沒有完整覆蓋進度 | 每輪刷新第 1 頁，其餘頁數預算接續上輪進度；成功入庫後才保存游標。續頁明確 404 時重設第 2 頁，保留診斷 |
| 好房住宅內文的「含車位」造成整筆刪除 | 房型判讀使用標題／格局；停車設備不再覆蓋住宅格局。租租通以結構化 type_space 優先 |
| 某頁／某區失敗使之前成功批次消失；格式錯誤誤算成功 0 筆 | 保留成功資料並回傳分區／頁碼／錯誤碼；要求上游總數與內容結構有效。403／429 會停止該來源本輪後續請求，租租通詳情同樣適用 |
| 每次列表與統計先 UPDATE 過期刊登，可能各等待 SQLite 寫鎖 8 秒 | 查詢改用既有到期時間條件排除過期刊登；查詢本身不再寫入過期狀態 |
| 全庫 SELECT *、逐筆查個人同屋源、全量裝飾卡片 | 候選只讀篩選／排序所需欄位；個人同屋源一次讀取；排序後才載入本頁完整說明、照片、設備和比較資料 |
| 比較排序時重複解析價格／日期；較適合為每筆生成完整卡片 | 排序鍵只計算一次；較適合只計算必要分數，完整卡片留至分頁之後 |
| 統計缺費用／聯絡人等篩選欄位，快取鍵不含完整覆寫條件 | 與候選查詢共用必要欄位；快取包含使用者、完整設定及資料庫變更版本；路線失敗狀態批次讀取 |

## 驗證

- `node --test v3/test/source-recovery.test.js v3/test/list-query-regression.test.js`：涵蓋搜尋關聯、來源失敗、房型判斷、游標、同屋源識別、跨帳號隔離、費用、完整結果分頁與外部寫鎖。
- 外部 SQLite 連線持有 `BEGIN IMMEDIATE` 寫鎖時，少量資料的列表加統計仍在 1 秒內完成，過期自家刊登仍被排除，且查詢未寫入資料庫。
- 全套 `npm test` 與未修改基準版本比對：基準已有 17 個失敗，集中在已移除的部署 workflow、既有畫面色碼與過時排序／統計斷言；本修正沒有新增同類失敗。完整測試數量以 PR 驗證紀錄為準。
- `node v3/benchmark-listings.mjs` 永遠建立獨立暫存資料庫，產生 64,000 筆合成刊登，每頁 50 筆；比較基準與修正版本的總數、頁面順序／分數摘要。它不連線正式資料庫、不抓外站。
- 此環境同條件基準列表查詢約 3.6～8.1 秒；修正後約 1.2～2.8 秒。包含未命中快取的統計仍需額外時間。測量不是 NAS 的端到端延遲或服務保證。
- `/api/listings` 現在分別回報 `query_ms`、`stats_ms`、`total_ms`，並有 `Server-Timing`，方便正式環境區分查詢與統計；不包含網路傳輸與前端繪製。

## 正式環境尚待驗證

1. 透過正式後台核對三個來源開關、各來源庫存／可見數量與最近一次抓取錯誤；目前只能確認公開示範列表含好房資料，不能由示範前 30 筆推算租租通／樂屋全庫數量。
2. 本環境直接請求樂屋曾收到 Cloudflare 403。沒有繞過驗證、切換代理或提高頻率。這不能證明 NAS 同樣被擋。
3. 新樂屋卡片解析是依公開頁欄位與連結形式實作的保守相容分支，測試中的現代卡片 HTML 是重建範例，並非成功取得的原始 DOM。需在正式站取得正常回應後保存去識別化 fixture，核對分頁參數與模板；未知模板必須 PARSE_FAILED，不能宣稱成功無物件。
4. 現代卡片只證實行政區時保留 district_only，不將社區名當門牌，不生成座標。低精度同屋源鍵包含來源物件 ID，避免兩間不同住宅因同區／同坪數誤合併。完整地址與內頁欄位仍需正常詳情回應才能補齊。
5. 部署只走既有 Build production image → Production predeploy check → Deploy v3 三條 workflow，使用同一 master SHA／不可變 image digest。不得用直接 SSH 啟動容器替代既有部署流程。
6. 發布後以相同設定、行政區、房型、排序測至少冷查詢及連續切換，記錄 API Server-Timing 與瀏覽器端完成時間；核對總數及逐頁不重複、不遺漏，再確認來源恢復。

每頁上限能降低傳輸與繪製成本；現有 API 預設已是 80 筆。本次保留使用者現有分頁契約，先修後端重複工作與寫鎖等待。地圖找房保留下一版規劃。
