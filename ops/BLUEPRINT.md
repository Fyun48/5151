# OPS／多站藍圖（完整、雙向、不打死結）

給 Owner 讀的總稿。短表在 [`PLAN.md`](PLAN.md)，v3 外掛細節在 [`../v3/PLAN-integrations.md`](../v3/PLAN-integrations.md)。  
**理想只有一句：每個公開站沒有 OPS 也能營業；OPS 沒有某一個站也能活。兩邊都是訂閱關係，不是器官移植。**

Owner 直接下令改程式並部署，永遠不必走這條線。

---

## 0. 我想做成什麼

不是「一個神站管死所有站」，而是一座**可掛、可卸的工作臺**：

- 你的吉比租房、以後你自己的第二／第三個站、以及你幫別人做還在營利的站，都可以**掛上來**給你看回饋、評估、做版本、抽去識別洞察。
- 任何一站都可以**卸下來**：對方帶走自己的程式、資料庫、意見箱、站內 CRM、外掛金鑰。你的 OPS 少一張產品卡，其它站不受影響。
- 付費外掛、製作 AI、測試站、自動上正式機，全部是**可開可關**。關了就回到已經在跑的免費／手動路徑，站不會停。
- 我替你做的每一塊，都要能「裝上」也要能「拆掉」。拆掉之後行為等於今天，或等於該站加入 OPS 之前。

這就是雙向：進來不是單向門，出去不是拆引擎。

## 1. 兩層世界（先分清，才不會打死結）

```
                    你的 OPS（控制臺）
                    ops.db / 5151-ops / jibbyrentops
                   ↑ 訂閱複本、指標、議題      ↓ 只觸發「已存在的部署按鈕」
                   │ 絕不當對方的主資料庫      │ 絕不 SSH 進對方營業庫亂寫
  ┌────────────────┼───────────────────────────┼────────────────┐
  │ 站 A 吉比租房   │ 站 B 你的下一站            │ 站 C 幫別人做的營利站 │
  │ 自己的容器/庫   │ 自己的容器/庫              │ 自己的容器/庫         │
  │ 意見箱在本機    │ 意見箱在本機               │ 意見箱在本機          │
  │ 外掛金鑰在本機  │ 主題色在本機               │ CRM 本體在本機        │
  └────────────────┴───────────────────────────┴────────────────┘
```

**運行時單向：** 站 → OPS（抄回饋、可選抄指標）。OPS 不在對方頁面渲染路徑上。  
**治理時有限回寫：** 只有你在 Gate #2 同意後，OPS 去按該站「已經存在、受保護」的 Deploy。沒有同意就沒有回寫。  
**分家時反向：** OPS → 匯出包給對方，然後停訂閱。不是對方站來跟 OPS 要資料才能開張。

打死結的典型做法（我們不做）：

- 意見表單打不開 OPS 就 500
- 會員名單只存在 OPS
- 部署 v3 必須先部署 OPS，部署 OPS 必須先部署 v3
- 製作 AI 不做完就不能取消議題
- 預算燒光沒有 fallback，爬蟲整站停

## 2. 雙向地圖（每一種關係都要有「去」與「回」）

### 2.1 公開站 ↔ OPS（加入／退出）

| 去（加入） | 回（退出） | 卡死點與破解 |
| --- | --- | --- |
| 站內已有 `feedback` 表與後台 | 表與後台不動 | 若先做「只寫 OPS」才會卡；禁止 |
| 登記產品卡、發一把 ingest 密鑰 | 作廢密鑰、停用產品卡 | 密鑰只停這一站，其它站各一把 |
| `OPS_FEEDBACK_DELIVERY=1` 抄複本 | 設回 `0` 或清空 URL | 遞送失敗只重試 outbox，**不回滾本機回饋** |
| （可選）抄 CRM／花費指標 | 停抄；可匯出後清除 OPS 複本 | OPS 清複本不准 `DROP` 對方正式庫 |

v3 **今天已經是左欄的「去」可隨時走右欄**：遞送預設關；後台「使用者回饋」讀本機。缺的是 Console 一鍵退出包，不是缺本機意見箱。

### 2.2 回饋本體 ↔ OPS 複本

```
使用者送出
  → 站的 feedback 列（主本，狀態：待看／已排入／…）
  → 同交易寫 outbox（即使遞送關著也留紀錄，可稽核）
  → 若開啟遞送：HMAC 抄到 OPS
  → OPS 分群／評估（可關）
```

回：OPS **不改**站上那一列的內容。你在 OPS 按「核准開發」只改 `ops.db`。  
對方站長在自己後台改「已完成」，不必通知 OPS。兩邊狀態允許暫時不一致；不一致不是死結。

### 2.3 評估 → 你核准 → 製作 → 測試 → 你再核准 → 上線 → 退回

程式裡已有生命週期（`ops/src/stateMachine.js`）。用白話標出**每一格的出口**，沒有「只能進不能出」：

```
收集中 ──你可以取消──► 已取消
   │
   ▼
評估中 ──建議做──► 等你核准開發（Gate #1）
   │                │ 核准 → 已核准開發 → 製作中 → 測試 → 測試站 → 等你核准發布（Gate #2）
   │                │ 要改／暫緩／拒絕／封鎖／取消  ← 都是合法出口
   │                ▼
   │         發布中 → 已發布 → 你可退回上一版程式
   │                │ 失敗 → 可回製作或取消
   │                ▼
   └──暫緩／拒絕──► 要再評估必須「達門檻重評」或你解除封鎖
                    BLOCKED 不會自動醒；你可解除或取消（不是死，是鎖，鑰匙在你）
已發布 不准退回「同一條開發生命」重做；新問題開新議題（避免舊單循環污染）
```

**等你按按鈕不是死結**，是門。門的另一邊永遠有：核准、退回、取消、封鎖、重開新單。  
製作 AI 掛了：議題可取消或標記失敗，測試站 TTL 到了就拆，不佔正式機。  
Gate #2 你一直不按：不上線，測試站到期清理，正式站維持舊版。  
退回之後：正式站是上一版 digest；若還要改，走重評或**新議題**，不准把已發布單倒回開發中（避免歷史被改寫、審計斷鏈）。

### 2.4 製作 AI／金鑰（開／關／換人）

| 去 | 回 |
| --- | --- |
| 後台貼金鑰、開某個抽屜 | 關抽屜；金鑰可刪。進行中的任務取消，不刪已開的草稿 PR（你可在 GitHub 關） |
| 這張議題指定 Claude | 下一張指定別人；舊指定不綁死全站 |
| Cursor Agent 尚未接上 | 走「通知你、你指定人做」——本來就是 fallback，不是半套 |

關抽屜後：回饋照收。只是不再自動分析／不再自動寫碼。沒有「關了就收不了意見」。

### 2.5 測試站（掛上／拆掉）

| 去 | 回 |
| --- | --- |
| 每站一個長期 staging 容器＋獨立空庫 | `docker` 停掉或清 volume；正式庫從未掛上去，所以拆測試站不傷營業 |
| 用某 SHA 佈上去給你點 | 換回空殼或上一個測試 SHA；TTL／你按清理 |
| Access 只准你 | 拿掉 hostname 或關 Access，正式 Tunnel 的 c5151 不動 |

### 2.6 正式部署（同意／反悔／退回）

| 去 | 回 |
| --- | --- |
| Gate #2 同意 → 觸發該站既有 Deploy（v3 就是 Deploy v3） | 拒絕／取消 → 不觸發 |
| 發布成功，記下「新 digest + 上一版 digest」 | 退回＝再 Deploy **上一版 digest**（程式） |
| 你要連資料一起回到發布前 | **另一次**高危險確認；預設不做。這是避免「退回程式卻默默抹掉新會員」的死結 |

OPS 自己不持 NAS 密碼當常態路徑。Deploy 工作流已經 fail-closed。OPS 只是幫你按那顆既有的按鈕。

### 2.7 外掛／預算（v3 站內，與 OPS 無關）

| 去 | 回 |
| --- | --- |
| 後台開 ZenRows／代理／Qwen／距離 | 關開關或預算 0 → 立刻走現有直連／Haversine／`match.js` |
| 燒到日／月上限 | 硬熔斷＋記 `budget_exceeded`，當天不再打付費，爬蟲繼續用免費路徑 |
| 外掛 401／429 | 記 error，該次 fallback，不是整站停爬 |

`daily_budget_twd = 0`＝不准花錢，不是無限。這是防止「空白表單＝無上限」的死結。

### 2.8 CRM（掛上／卸下）

| 去 | 回 |
| --- | --- |
| 站內 CRM 套件（對方經營者也用） | 資料在該站庫；卸 OPS 仍在 |
| OPS CRM 訂閱複本（只有你） | 退出時匯出＋停用＋可清除。預設留下的只有去識別主題 |
| 你要用跨站洞察做下一項服務 | 只用聚合；要可識別資料必須產品卡另勾，退出可刪 |

禁止：OPS CRM 寫回對方會員表。那會變成「對方改一筆、你改一筆」的雙主死結。

### 2.9 設計系統（抽出／留下）

| 去 | 回 |
| --- | --- |
| 從 v3 抽出 token＋共用按鈕／表單 | v3 改引用抽出檔；若抽出失敗，v3 仍有自己的 `tokens.css` |
| 新站只覆寫配色 | 新站可隨時改回自己的 `:root`，不強制連回 design-system |
| OPS Console 以後改吃同一套 token | 可關；Console 現有灰綠仍能獨立活 |

物件卡、許願房留在「產品區塊」，不強迫其它行業站引用。這樣不會出現「卸租屋站、別的站按鈕全壞」的死結。

### 2.10 同一個 GitHub ↔ 對方自己維護

這是最容易打死結的地方，必須講死：

| 去 | 回 |
| --- | --- |
| 開發時放在你的 monorepo（方便你一人維護） | 分家給**程式快照**（該站目錄＋其 lockfile＋其 compose＋其 DB），對方開自己的 git |
| 你繼續改 `master` | 對方不再 pull 你的 `master`（避免你以後的 OPS／v3 變更灌進他們營業站） |
| 同一條 Tunnel 暫時掛他們的 hostname | 分家當天改 DNS／Tunnel 到他們自己的機器，或他們自己開 Tunnel。**不是**留在你 NAS 上卻假裝獨立 |

「程式在同一個 repo」≠「運行必須綁在你的部署」。分家切的是**營運權與 git 來源**，不是把目錄從磁碟蒸發。

## 3. 資料怎麼流（可來可去，沒有環狀運行依賴）

```
[站的使用者] → [站 DB 主本] →（可選）→ [OPS 複本] → 議題／評估／你的洞察
                     ↑                        │
                     └── 禁止這條當營業路徑 ◄──┘
                           （OPS 當機，站仍要能收意見、登入、爬蟲）

[你 Gate #2 同意] → [該站的 Deploy 工作流] → [該站正式容器]
[你退回]           → [同一工作流 + 上一版 digest]
```

OPS 當機：各站 outbox 堆積，遞送稍後再送；或你關掉遞送。站的意見箱不依賴 OPS 健康檢查。  
某站當機：OPS 少新回饋，其它站與 Console 仍在。  
v3 外掛當機：fallback 免費路徑。  
這三個「誰當機誰還活」就是沒有環。

你要的「抓可用資料做下一個服務」走**側路**：

1. OPS 定期把已退出或仍掛著的站的複本做成**主題計數**（去識別）。
2. 寫進 OPS 自己的「靈感庫」，不寫回任何正式站。
3. 退出勾選「刪可識別資料」時，靈感庫裡若還有 email／電話必須一起刪。

## 4. 我依序要做的事（每一包都可拆掉）

下面是我替你做的工作包，不是日曆。每包寫「做什麼／不做什麼／怎麼反悔」。做完一包就該能單獨上線。

### 包 0 — 文件與認路（進行中）

- GitHub 首頁看出兩套上線物；`PLAN.md`／本檔／`v3/PLAN-integrations.md`。
- 反悔：刪文件不影響任何容器。

### 包 1 — Deploy OPS（常態不再靠 SSH 改 NAS）

- GitHub 手動工作流：只 SCP `ops/`，只重建 `5151-ops`，確認字串、只准你的 actor。
- **不**碰 `591-tracker-v3`，**不** Deploy v3。
- 反悔：不跑這條 workflow；OPS 容器維持現況。

### 包 2 — 產品卡（先能掛 v3，結構預留多站）

- OPS 裡 `product` 實體：id、顯示名、ingest 密鑰、遞送開關、repo 子目錄、部署工作流名。
- Console 頂部可切「全部／某站」。收件匣帶產品標。
- 反悔：只留 v3 一張卡；查詢預設全部。各站遞送開關仍在各站 env。

### 包 3 — 一鍵退出包（分家）

- 按鈕：停用卡、作廢密鑰、列出匯出清單（程式快照指引、DB、本機回饋、本機 CRM、env 模板）。
- 可選：清除 OPS 內該站可識別複本，保留去識別計數。
- **不准**停對方容器、不准刪對方 volume、不准關對方意見表單。
- 反悔：產品卡可再啟用、換新密鑰重新加入（雙向）。

### 包 4 — OPS 供應商抽屜（分析／通知先，製作預設關）

- 後台貼金鑰、開／關、測試 webhook。
- 製作抽屜可看見「未接上／用通知人工做」。
- 反悔：全關＝今天的 stub／不呼叫。

### 包 5 — v3 測試容器

- `591-tracker-v3-staging`，`127.0.0.1:5155`，獨立 volume，可選 Access hostname。
- 反悔：停容器、刪 staging volume；正式 5153 無感。

### 包 6 — Gate #2 畫面 + 通知

- 變更檔案、SHA、digest、測試站連結、同意／拒絕。
- 同意後若 live 仍關，只顯示「請你走現有 Deploy v3」，不偷偷 dispatch。
- 反悔：拒絕、取消、或根本不開 live。

### 包 7 — Phase 15 live（只按既有 Deploy）+ 程式退回

- 打開前必須：測試站你點過、Gate #2 UI 在、上一版 digest 有記。
- 退回＝Deploy 上一版 digest。資料庫還原另一道確認。
- 反悔：`PRODUCTION_RELEASE_ALLOW_LIVE=0` 立刻回到手動 Deploy。

### 包 8 — 站內 CRM 套件（給會分家的站）

- 可選表：聯絡人、備註、來源回饋 id。活在**該站 DB**。
- 反悔：不建表或 drop 套件表；意見箱不受影響。

### 包 9 — OPS CRM（只有你的工作臺）

- 分匣複本、連到議題、去識別靈感庫。
- 禁止寫回對方站。退出走包 3。
- 反悔：關模組；複本可清。

### 包 10 — v3 外掛／硬熔斷／pHash／LLM／爬蟲洞察

- 依 `v3/PLAN-integrations.md`：新表、`executeWithProvider`、先包一處 `fetchHtml`、後台卡片。
- 預設全關、0 元不花錢、距離 NT$50／LLM NT$20。
- 反悔：關開關＝與 3.51 行為相同（測試必須鎖這條）。

### 包 11 — 抽出 token 與共用元件

- `design-system/tokens.css` + 主題覆寫；v3、以後 OPS Console 引用。
- 反悔：v3 保留一份內建 token，抽離失敗可切回。

## 5. 我堅持的理想（用來審每一個 PR）

1. **本機為主。** 任何「給對方營業用」的功能，第一次寫入必須在對方站。OPS 只能有複本。
2. **關開關＝舊行為。** 外掛、AI、自動部署、CRM、遞送，預設關。
3. **失敗往下走，不往上炸。** 付費失敗 → 免費；OPS 失敗 → 本機；製作失敗 → 取消或重做，不上正式機。
4. **每一扇門都有人按得了。** 等你核准不是卡死；封鎖有解鎖；已發布不重寫歷史，只開新單或退回 digest。
5. **審計只追加。** 退出、退回、熔斷都留痕，不改寫舊列。
6. **金鑰分家。** 製作／OPS 金鑰不進 v3；v3 外掛金鑰不進 OPS；分家匯出不含別人的卡。
7. **同一個 repo 是開發便利，不是終身契約。** 分家給快照與獨立 git。
8. **你直接下令優先。** 投票線是給「使用者回饋堆起來」用的。

## 6. 用三個站把故事走完（證明可來可去）

**站 A** 吉比租房（你經營）：加入 OPS、開遞送、你用洞察做功能。永遠可以關遞送；關了意見仍在 v3 後台。外掛熔斷只影響付費路徑。

**站 B** 你的下一站：複製主題、套意見箱套件、登記第二張產品卡。A 的 Deploy 與 B 的 Deploy 分開。B 掛了不影響 A。

**站 C** 幫別家做、已營利：從第一天 local-first。你的 OPS 訂閱複本做品質監控。分家日：包 3 退出 → 他們拿走 C 的快照與庫 → 改 Tunnel／DNS 到他們機器 → 你清可識別複本、可留「當時很多人嫌結帳慢」這種句子。C 的意見箱、會員、外掛帳單都在他們庫裡。你的 A、B、OPS 繼續。

沒有一步需要「先拆 A 才能放 C」，也沒有一步需要「C 活著 OPS 才能活」。
