1. **投影不只是「少數列缺席」，而是大規模未回填**：86,533 筆（其中 85,002 筆可見）。

2. 因此 `listPublicListingsFast()`（`db.js:7100`）的註解「投影與 listings 筆數不一致時寧可回退完整的 Node 路徑」
   會在**正式環境幾乎永遠成立**（缺口 8.6 萬筆）→ 訪客路徑長期走同步 Node／SQLite，這也是 F1 的實際後果。

4. 依 ChatGPT 指令文件要求，回填**不得**直接以舊 SQLite 為真相、也不得先 `TRUNCATE` 再慢慢補；
   應以 PG 主列驅動、分批可重跑、同批一致、並在寫入路徑改為「主列＋投影同交易」之後執行。
