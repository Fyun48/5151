## 修改

- 列表與統計在讀取完整候選欄位、計算通勤與條件前，先用現有 `source_key` 的縣市／行政區前綴排除已知外區資料。
- 未知、缺少或非標準前綴仍交由原本地址／標題判斷，避免丟失歷史資料。
- 同房源關係的兩側、當前會員手動合併的成員仍保留給主副卡判斷。
- 統計的行政區過濾提前；共用搜尋底庫的下架計數另外以 SQL 計算，保留既有範圍。
- 所有排序仍在完整符合集合上執行，再分頁。沒有新增回應截斷、資料表遷移或讀取時寫入。

## 同屋源關聯造成的剩餘查詢成本

`99256bd996300a3f7592f7695772349f8844f1cd` 部署後，Owner 提供正式 API 回應：`query_ms=5318`、`stats_ms=1144`、`total_ms=6462`、`dataset=729`。相較先前 16,073 ms 已改善，但符合筆數從 822 改變為 729，不能把全部差異歸功於效能修改。

前一版為避免改變跨行政區主副卡判斷，保留全庫所有同屋源關係。這使大量與使用者行政區無關的物件仍進入 JavaScript、會員旗標覆寫、通勤與主副卡計算。第一輪跨區基準沒有大量同屋源關聯，未涵蓋這個負載。

本次以所選行政區（加上需要地址回退判斷的舊資料）作為起點，僅保留與其直接或間接相連的系統同屋源和當前會員手動合併成員。包含單向反向關聯、跨區鏈、循環、缺失的關聯目標；其他會員的合併不參與。所有既有 SQL 條件、會員旗標、主副卡規則與完整結果排序仍在後續套用。SQL 使用既有的關聯及個人群組索引；沒有新增資料遷移、網路請求或查詢時寫入。遞迴查詢以 `UNION` 去除重複 ID，循環會終止；做法參照 [SQLite 官方圖關聯查詢說明](https://www.sqlite.org/lang_with.html#queries_against_a_graph)。

64,000 筆合成資料中，51,200 筆具有關聯、1,600 筆位於所選區域、800 張主卡符合，每頁 50 筆。修正前／後同機測量：

## 連續操作與統計快取

PR #282 的 `4d8cd2d` 已部署，Owner 回傳同樣 729 筆符合的正式結果：列表 1,475 ms、統計 1,209 ms、總計 2,684 ms。比前次 6,462 ms 少 58%；列表少 72%。階段為準備 91、SQL 468、4,454 筆候選的條件處理 566、同屋源 78、顯示篩選 98、排序 9、卡片整理 160 ms。統計現在占約 45%，是下一項明確成本。

本次調整：

- 統計由單一快取改為最多 32 組、依會員／完整設定檔／搜尋範圍分開保存，普通有效期從 4 秒延至 15 秒。讀取不延長有效期，最近使用的項目優先保留；既有明確延長快取的呼叫仍受支援。
- 快取仍包含同連線 `total_changes()` 與其他 SQLite 連線 `data_version`。來源、個人標記、設定或其他資料庫寫入後即失效，沒有用較長 TTL 掩蓋資料更新。頻繁背景寫入仍可能降低命中率。
- 回傳複本，呼叫端修改計數不會污染快取。快取只保存純量統計，不保存列表卡片。
- 租金、關鍵字、刊登者、坪數等不依賴路線的條件先判斷，通過後才讀取路線快取和建立帶通勤欄位的資料；保留非嚴格通勤對「尚未算出路線」的原有處理。
- `timing.stats_stages` 新增 `cache_hit`、`cache_age_ms`；重新計算時另列準備、SQL、條件處理、計數耗時及候選筆數。

16 項相關測試通過，新增交錯會員／設定檔快取命中、過期不因讀取延長、32 組容量淘汰、複本隔離與通勤結果測試；既有個人標記、外部資料庫寫入失效及寫入鎖案例仍通過。
